# Creator Platform implementation contract

Personal local-first Chinese creator workbench. Original implementation inspired by reference architectures; no AGPL/GPL source copied. Node >=22.13, Express TypeScript backend + built-in SQLite, React/Vite TypeScript frontend. Bind localhost by default. No credentials provided; remote publishing must never be exercised by development tests.

## Ownership

- Root: root package/config, shared contract, server catalog/domain/storage/vault/API/queue/generation, tests for these, integration, docs.
- Connector agent: `server/connectors.ts`, `tests/connectors.test.ts` only. Native official APIs + Postiz + xiaohongshu REST + Wechatsync.
- Frontend agent: `client/**` only. Uses this contract, no server/root package mutations.
- Bridge/review agent: `client/bridge.ts`, `tests/bridge.test.ts` (front-end agent must import; do not edit this file), reference analysis, docs reference analysis.

## Domain / JSON contracts

`Platform`: `{id,name,shortName,region:'domestic'|'global',category:'article'|'social'|'video',color,description,titleLimit:number,bodyLimit:number,formats:string[],postizId?:string,multipostId?:string,wechatsyncId?:string,requiredMedia?:'image'|'video'|'any',recommendedTone:string,notes:string[]}`.

Catalog source of truth is `server/catalog.ts`: 102 targets (61 domestic, 41 global), including the original 34 plus publishing/blog/community/video and enterprise destinations. Presence in catalog means content adaptation, not configured publishing. Publishing path is connection-specific: 18 native, 32 Postiz mappings, 69 MultiPost keys, 17 Wechatsync draft keys, and XHS REST. Sets overlap. Four targets currently only support export/custom receiver. Never infer readiness from catalog presence.

`Profile`: `{id,name,audience,tone,language,description,forbiddenWords:string[],updatedAt}`.

`Content`: `{id,title,source,profileId?:string,media:Media[],createdAt,updatedAt}`. `Media`: `{id,name,url,mime,size}`; upload URLs `/uploads/<id.ext>` locally.

`Variant`: `{id,contentId,platformId,title,body,tags:string[],thread:string[],html?:string,source:'rules'|'ai'|'manual',issues:Issue[],approved:boolean,updatedAt,sourceRevision?:string}`. `Issue`: `{severity:'error'|'warning',message}`. Editing content invalidates variant approvals; editing a variant revalidates and clears approval. Explicit rebase binds retained wording to the current source revision and clears approval; approve only a valid variant in a separate request after review.

`Connection`: public `{id,name,platformId,connector,enabled:boolean,configured:boolean,config:Record<string,string>,secretKeys:string[],createdAt,lastTest?:ConnectionTest}`. `ConnectionTest`: `{at:string,ok:boolean,message:string,scope:'configuration'|'credentials'}`. Sensitive fields NEVER returned, represented by secretKeys. connector enum `postiz|xiaohongshu|wechatsync|multipost|webhook|native`. All keys encrypted at rest; public config excludes secret keys. `ConnectionInput` `{name,platformId,connector,config:Record<string,string>,enabled?:boolean}`. Empty/missing secret field on edit retains saved value. Saving changed platform, connector or effective configuration clears lastTest; changing only name/enabled preserves it. No test runs implicitly when saving. Configuration/credential checks do not guarantee publishing permission.

`Job`: `{id,batchId,contentId,variantId,connectionId,platformId,connectionName,title,status:'queued'|'scheduled'|'running'|'published'|'drafted'|'failed'|'unconfirmed'|'needs_action'|'cancelled',scheduledAt,attempts,message,remoteId?:string,url?:string,createdAt,updatedAt,snapshot:Variant}`. Individual per-target job. Draft/bridge/unconfirmed are never published. Unknown network outcomes never auto-retry. Explicit retry creates new job after user instruction, warning about possible duplicate in UI. Startup recovery of in-flight jobs becomes unconfirmed.

`Settings`: `{generation:{enabled:boolean,baseUrl:string,model:string,hasApiKey:boolean},timezone:string}`. Default no AI configured, deterministic rule adaptation accurately labelled.

`Bootstrap`: `{platforms:Platform[],profiles:Profile[],contents:Content[],variants:Variant[],connections:Connection[],jobs:Job[],settings:Settings,connectorDefinitions:ConnectorDefinition[]}`.

`ConnectorDefinition`: `{id,name,description,platformIds:string[],fields:{key,label,secret?:boolean,placeholder?:string,help?:string,required?:boolean}[],mode:'publish'|'draft'|'bridge'|'custom'}`. Native per-platform schema entries with `id:'native:<platformId>'`; connection connector stores `native`. UI filters definitions by platformIds and normalizes native:id to native.

## HTTP

All success responses direct JSON object/array (not data wrapper). Error `{error:string}`. JSON limited 2MB, uploads 25MB; secrets stored only server-side. Vite proxy `/api` and `/uploads` to :4318. Frontend dev :4317.

- GET `/api/bootstrap` Bootstrap. GET `/api/health` `{ok:true}`.
- POST `/api/contents` `{title,source,profileId?,media?}` -> Content; PUT `/api/contents/:id` same fields -> Content; DELETE content -> `{ok:true}` (reject active jobs).
- POST `/api/contents/:id/generate` `{platformIds:string[],mode:'rules'|'ai',replaceExisting?:boolean}` -> `{variants:Variant[],mode:string}`. replaceExisting defaults to false: any existing selected-platform version causes HTTP 409 before generation, preserving all versions. The normal UI requests only missing versions. Only explicit true replaces selected existing versions; unselected versions are preserved. AI configuration is required for ai; failures surface errors, never silent fallback. Selected version baselines, source revision and profile are checked again before commit; concurrent changes cause HTTP 409 and preserve current edits. All AI batches must succeed before any versions are committed. Output creation preserves source text and validates constraints.
- PUT `/api/variants/:id` `{title?,body?,tags?,thread?,approved?:boolean,rebase?:boolean}` -> Variant. Approved-only request approves existing valid unchanged text. Any text mutation clears approval regardless the requested boolean. Explicit `{rebase:true}` retains wording, binds sourceRevision to the current source and revalidates; it always clears approval, even with approved:true in that request. The UI asks the user to review the current source before rebasing and sends a separate approval request afterward.
- POST `/api/profiles`, PUT `/api/profiles/:id` -> Profile; DELETE -> `{ok:true}`.
- POST `/api/connections`, PUT `/api/connections/:id` -> public Connection; DELETE -> `{ok:true}`. POST `/api/connections/:id/test` -> `ConnectionTest` directly (no wrapper); the same sanitized result is persisted as Connection.lastTest, including failed checks and validation/errors. scope=configuration for MultiPost, native Slack/飞书/钉钉/企业微信/Teams, and a custom webhook without healthUrl; remaining read-only credential/service checks use scope=credentials. A configuration change during a check returns HTTP 409 and prevents attaching the old result to the new configuration.
- PUT `/api/settings` `{generation?:{enabled?,baseUrl?,model?,apiKey?},timezone?}` -> Settings; blank apiKey retains, explicit clear key via `clearApiKey:true`.
- POST `/api/jobs` `{contentId,targets:{variantId,connectionId}[],scheduledAt?:ISO}` -> `{jobs:Job[]}`. Only approved valid variants and enabled configured compatible connections allowed. De-duplicate request with `Idempotency-Key` header; server returns original jobs.
- POST `/api/jobs/:id/cancel`, POST `/api/jobs/:id/retry` -> Job.
- POST `/api/jobs/:id/confirm` `{outcome:'published'|'drafted'|'failed',url?:string,message?:string}` -> Job, only needs_action or unconfirmed; human confirmation labelled in message.
- POST `/api/jobs/:id/bridge` `{outcome:'dispatched'|'failed'|'unconfirmed',message?:string}` -> Job. Only MultiPost needs_action accepts a handoff receipt. dispatched remains needs_action, never published; failed means explicit rejection or failure before sending; unconfirmed means timeout, missing receipt or an unknown result and moves the job to unconfirmed. An unconfirmed job cannot be handed off again through this endpoint; the user must first inspect the extension and target platform before confirming an outcome or explicitly retrying.
- GET `/api/contents/:id/export?platformId=...&format=markdown|html|json` file download.
- POST `/api/uploads` multipart `file` -> Media. GET `/uploads/:file` safe static media.

## Connector module interface (agent-owned)

Export `getConnectorDefinitions(platforms:Platform[]):ConnectorDefinition[]` and `validateConnection(connection:ConnectionPrivate,platform:Platform):string[]`, `testConnection(connection,platform):Promise<{ok:boolean,message:string}>`, `publish(connection,platform,variant,media,context):Promise<PublishResult>`.

`ConnectionPrivate`: `{id,name,platformId,connector,enabled:boolean,config:Record<string,string>}` (decrypted config; never log). `PublishResult`: `{status:'published'|'drafted'|'unconfirmed'|'needs_action',message:string,remoteId?:string,url?:string}`. Throw errors with `uncertain:boolean` when mutation outcome is unknown; export `ConnectorError`. `PublishContext`: `{publicBaseUrl:string,readMedia:(media:Media)=>Promise<Uint8Array>,localMediaPath?:(media:Media)=>string,signal?:AbortSignal}`. The optional path is only for a same-host loopback XHS video service; it must never be sent to a remote service. Use fixed official endpoints or user-configured services. Timeout POST once means unconfirmed, not safe to repeat. No fake publishing. Validate media limitations. SDK-free fetch/FormData. Tests MUST mock network and never use real services. Enterprise protocols live in `server/enterprise.ts` and are dispatched through the total connector entry.

## MultiPost bridge module (agent-owned)

Export `detectMultiPost(timeoutMs?:number):Promise<{installed:boolean,platforms:any[]}>`, `dispatchMultiPost(platform:Platform,variant:Variant,media:Media[],timeoutMs?:number):Promise<{dispatched:boolean,outcome:'dispatched'|'failed'|'unconfirmed',message:string}>`. dispatched=true requires an explicit received receipt with extension ID and still says nothing about publication. Only accept responses matching trace ID + own window source + correct message envelope. Sanitized platform body mapped to article/dynamic formats. Developer/user must add localhost to extension trusted domains if required. Known rejection/pre-send failures return failed; timeouts and ambiguous receipts/errors return unconfirmed without automatic resend. Return actionable messages and remove listeners after settlement.

## UI

Chinese, deliberate local creator editor, neutral light palette with single forest-green accent, system CJK sans. Left slim nav: 创作工作台 / 内容库 / 发布任务 / 平台目录 / 发布账号 / 写作画像 / 工作区设置. The workbench has three stages: 写原稿 → 适配与审阅 → 分发. Directory and Studio picker support search/region/format/capability filters and batch selection. Directory configure links preselect a platform. Main editor keeps source and platform versions separate; approval precedes per-account publish/schedule. Empty state truthful; load example inserts editable content only, never fake connections/jobs. Sensitive inputs remain blank + saved status. Needs-action jobs allow foreground bridge dispatch followed by human confirmation. No auto dispatch from unopened browser page. Generation accepts the full catalog; AI processes sequential batches of six and persists only after all succeed. One job request allows up to 200 account targets.
