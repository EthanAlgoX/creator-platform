# 功能梳理与界面改版

## 核心工作流

「写原稿 → 适配与审阅 → 分发」是同一份内容的三个阶段，可以返回修改。导航包含七个页面：**创作工作台、内容库、发布任务、平台目录、发布账号、写作画像、工作区设置**。内容库管理稿件；发布任务管理审核快照和实际结果；平台目录帮助选目标；账号、画像和设置按需进入。

| 对象 | 负责的内容 | 状态与限制 |
| --- | --- | --- |
| 原稿 | 主题、正文、素材、画像 | 浏览器临时备份与服务器保存分别提示；保存修改会撤销旧审核 |
| 平台版本 | 针对某一平台的标题、正文、标签或串帖 | 待审阅 / 已修改 / 格式错误 / 原稿有更新 / 已确认 |
| 发布账号 | 平台、账号名称、发布方式、参数 | 参数不完整 / 待检查 / 参数检查通过 / 凭据检查通过 / 检查失败 / 停用 |
| 发布任务 | 某一版本与某一账号的审核快照 | 执行、排期、结果待核对、浏览器待操作、公开发布、草稿、失败、取消分别记录 |

## 已完成的功能与逻辑修复

- 同一屏同时写原稿、选 102 平台、审阅和配置发布，缺少操作重心：拆分三个工作区，主操作随阶段变化。
- 小字号、低对比度、重复标题和过大留白阻碍扫描：统一可读字号、文字对比度与控件间距，导航和内容分层。
- 平台目录铺满 102 张大卡片，重要限制藏在展开项：用紧凑列表和当前平台详情，提供“加入本次创作”。
- 原稿全部清空可能误判无修改：已有原稿直接逐字段比较，空内容也阻止误发布。
- 重新生成会替换人工稿件：默认仅生成缺失平台；重新生成展示替换范围，明确确认后才发送 `replaceExisting:true`。后端在提交前检查原稿、画像以及目标版本基线，冲突时保留最新编辑；AI 分批失败不会部分替换。
- 已排期快照与新版本 ID 脱节，可重复安排：按稿件 / 平台 / 账号阻止活跃重复；队列可以查看完整快照。
- 原稿修改后无法直接保留原平台文案再审阅：新增「核对原稿，保留当前文案」。明确操作先执行 `rebase`，重新绑定当前原稿并清除审批，再独立重新校验、确认。
- “参数齐全”误称“可用账号”：持久化账号 `lastTest` 的时间、结果、说明及检查范围。参数检查与凭据检查分开显示；账号配置变更清除旧结果，名称和启停变更保留；检查期间配置变化不会写回过期结果。
- 管理页编辑离开时缺少保护，创建成功后刷新失败可能诱使重复创建：统一未保存保护，写入结果与列表刷新分开反馈。
- 人工核对默认已发布：结果必须主动选择；重试明确沿用旧快照。
- 扩展超时被误记为失败：交接返回明确的 `dispatched`、`failed` 或 `unconfirmed`；未收到回执、未知错误和不完整响应均待核对。未知任务不能直接再交接，不自动重试。

管理页面采用可筛选列表、任务快照弹窗与按需编辑表单。102 个平台、各连接器接入条件和真实权限边界保留，账号或稿件为空时提供真实下一步提示。

## 界面方向

Operate 模式。白色编辑区、冷灰页面底、深墨色导航和单一绿色主操作；系统中文字体，正文 14–16px，标签 13px，辅助说明至少 12px。写作区域占主要空间，配置按需进入。阶段导航提供真实进度，不展示虚构统计。移动端按阶段堆叠，平台与版本用可搜索选择，任务详情可以滚动。
